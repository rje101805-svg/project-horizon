# P2S7.1 manual acceptance — host start, spectating and match lifecycle

Scope: P2S7.1 only on `work`. P2S1–P2S6 remain accepted; alien melee still has no cooldown. No P2S8 systems, deployment settings or tracked Pages artifacts changed.

## Local setup

Pull `work`, install with `npm ci`, then run `npm run server` and `npm run dev` in separate terminals. For optional existing self-damage/refill controls, start the server with `NODE_ENV=development` and `COMBAT_DEBUG=1`. Those controls remain DEV-only and explicitly server-gated. Set the server URL to `http://localhost:3001`. Use visible windows for A and B; a third window C tests late joins. Give players different names.

## Acceptance checks (request flows A–E are covered below)

1. **Waiting:** A creates a room alone. Match status says waiting for host start; the disabled host button explains that at least 2 humans are needed. No winner/draw overlay. Waiting retains the existing solo flight/combat sandbox, but last-human logic never runs. B joins: the room MUST remain waiting. A sees enabled START MATCH; B sees WAITING FOR HOST and cannot start. A presses START MATCH: the server starts round 1, roster A/B, count 2.
2. **Victory:** A eliminates B with ordinary shooting. B becomes ALIEN/dead, count 1, match ends. A sees `VICTORY`, B sees `A's display name WINS`. B's pending alien respawn is canceled because the round ended. The overlay remains visible for approximately 6 server seconds.
3. **Freeze:** During those 6 seconds, both players hold fire/attempt movement and reload. Neither can damage, move, fire meaningful attacks, respawn or alter the result. Projectiles from the finished round are cleared. Existing DEV damage/reset/refill requests cannot bypass the freeze.
4. **Reset/opposite winner:** After 6 seconds, both reset to normal opaque human ships and normal HUD, 100 HP, 50 shield, 12 ammo, no reload/melee/protection/death residue. Overlay clears; the room stays waiting even with both players connected. A presses START MATCH again for round 2. Have B eliminate A. B sees `VICTORY`, A sees `B's display name WINS`. Repeat reset; no stale input, prediction, hit feedback or bullets should cross round boundaries. Inspect the formerly alien ship from both its own window and the other player’s window: normal human triangular hull, original player color, full opacity, no ghost silhouette/ALIEN tag/message, and normal projectiles. Verify this for B after round one and A after round two; the winner must also remain normal.
5. **Disconnect/result lock:** In an active A/B round, B leaves/disconnects while human: A wins. If A then disconnects during ended, an observing late joiner still sees A's original name/result; it must not change to a draw or a different winner. If fewer than 2 players remain after reset, status returns to waiting with no result. Another eligible player joining makes the new host’s START MATCH available; joining alone never starts a round. While waiting, separately test A leaving with B present: B becomes host, stays waiting alone, and can start only after C joins. Also check host departure during active play preserves winner/disconnect rules and ownership for the next waiting state.
6. **Late joins:** Join C while A/B round is active. C sees `SPECTATING · JOINS NEXT ROUND`, follows a living roster player with the camera, and sees the eventual result. With three original participants, eliminate/disconnect the followed player while at least two humans remain: C should follow another valid participant. At ended, following stops and the authoritative result displays. C has no gameplay ship, cannot fly/shoot/melee/reload, take damage, block bullets, become alien or count toward surviving humans. End the A/B round. At reset A/B/C become humans waiting for the host. They do not start automatically. A presses START MATCH to establish the new three-player roster, count 3. Eliminate B while A/C live: match stays active and all P2S6 alien respawn/melee/protection behavior remains available. Alien B leaving does not end the round or change count 2.
7. **Draw:** A legitimate reciprocal/trade kill in the same simulation tick must produce `DRAW` for all clients, never an alien winner. The result freezes and resets identically. For deterministic development verification, run `npx tsx --test --test-name-pattern='same tick reciprocal' tests/match.test.ts` and `npx playwright test tests/match.spec.ts --workers=1`: the real projectile path resolves both lethal bullets before the server evaluates the result; the browser cases verify DRAW from server snapshots. No public client draw/winner command or clock control was added. Manual trade reproduction can use point-blank opposing human shots after reducing shields/HP with existing development self-damage controls; exact network/tick timing may require retries.
8. **Latency:** Enable the visible DEV fake network checkbox and optional ±30ms jitter for A/B (outside F3, OFF by default, ON shows 150ms each way) before repeating victory, freeze and reset, and test spectator-to-participant transition. All clients must agree on round, roster and result. Human gun cadence, reload, prediction/reconciliation and active-round P2S6 melee damage/range/protection remain unchanged. No duplicate starts/results, stale overlays, double resets or alien visuals after reset. All clients return to waiting, the host button returns, and spectators become eligible. Disable fake network and confirm OFF. The header and footer must both identify Step 7; footer says `Phase 2 · Step 7: match lifecycle`.

## Architecture and checks

`shared/match.ts` defines replicated waiting/active/ended state, monotonic round, locked roster, discriminated winner/draw result, simulation-time end timestamp and reset remaining duration. `server/match.ts` owns transitions and six-second reset in the existing fixed tick. Winner detection runs after the entire player/projectile damage batch, enabling trade draws. Disconnect removal immediately evaluates an active round only. Winner ID/name are copied at end and never recalculated during ended.

Private `gameplayEnabled` gates central damage/resources, movement, respawn and fire APIs. OUT late joiners are excluded from target collision and melee. Ended freezes all connected players, clears projectiles and cancels respawn deadlines. Reset validates every safe spawn before atomically restoring connected players, synchronizing player simulation clocks and clearing alien/combat/lifecycle residue and returning to waiting regardless of connected count. Only a subsequent validated host request creates the next locked roster. It preserves membership identity and monotonic request counters while advancing life/teleport markers. Projectile IDs also remain monotonic. No per-player/room timeout or new frame loop.

The client renders result names via textContent only, never computes a winner from counts. Match boundaries clear delayed input/action callbacks, prediction/projectile visuals, held keys and hit feedback. Existing prediction/reconciliation logic stays unchanged during gameplay. Spectator ships are not rendered. The existing camera follows the empty local anchor repositioned to a valid rendered roster ship; unavailable targets are replaced, and ended/reset stop spectator following. No additional frame loop or free-camera controls.

The creator is the initial server-owned host. On departure, insertion order selects the first connected eligible human, falling back to the first remaining member for future-round hosting. Host identity is replicated in match state. The start event resolves sender/room from the socket, requires current host, waiting state, two eligible humans and a strictly validated current round token, rejecting spoofed fields and delayed prior-round starts. Host status never changes winner eligibility.

## Reset render regression

`tests/match-render.spec.ts` exercises two consecutive rounds with opposite eliminated players, in normal and 150ms/jitter modes. It compares the actual Phaser hull drawing commands (geometry and color) against the initial human hull on both local and remote clients, checks opacity/tag/message/resources, and sends a real client fire intent after each reset to verify human ammo consumption and authoritative projectiles. Checking only the cached alien boolean missed the original bug: the transition handler always redrew alien geometry even when that boolean became false. Hull creation and status transitions now share the same status-aware drawing function.
