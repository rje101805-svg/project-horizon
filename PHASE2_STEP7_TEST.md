# P2S7 manual acceptance — winner logic and match lifecycle

Scope: P2S7 only on `work`. P2S1–P2S6 remain accepted; alien melee still has no cooldown. No P2S8 systems, deployment settings or tracked Pages artifacts changed.

## Local setup

Pull `work`, install with `npm ci`, then run `npm run server` and `npm run dev` in separate terminals. For optional existing self-damage/refill controls, start the server with `NODE_ENV=development` and `COMBAT_DEBUG=1`. Those controls remain DEV-only and explicitly server-gated. Set the server URL to `http://localhost:3001`. Use visible windows for A and B; a third window C tests late joins. Give players different names.

## Acceptance A–H

1. **Waiting:** A creates a room alone. Status says waiting for at least 2 humans. No winner/draw overlay. Waiting retains the existing solo flight/combat sandbox, but last-human logic never runs. B joins: the next server tick starts round 1, roster A/B, count 2.
2. **Victory:** A eliminates B with ordinary shooting. B becomes ALIEN/dead, count 1, match ends. A sees `VICTORY`, B sees `A's display name WINS`. B's pending alien respawn is canceled because the round ended. The overlay remains visible for approximately 6 server seconds.
3. **Freeze:** During those 6 seconds, both players hold fire/attempt movement and reload. Neither can damage, move, fire meaningful attacks, respawn or alter the result. Projectiles from the finished round are cleared. Existing DEV damage/reset/refill requests cannot bypass the freeze.
4. **Reset/opposite winner:** After 6 seconds, both reset to normal opaque human ships and normal HUD, 100 HP, 50 shield, 12 ammo, no reload/melee/protection/death residue. Overlay clears; round 2 starts automatically. Have B eliminate A. B sees `VICTORY`, A sees `B's display name WINS`. Repeat reset; no stale input, prediction, hit feedback or bullets should cross round boundaries.
5. **Disconnect/result lock:** In an active A/B round, B leaves/disconnects while human: A wins. If A then disconnects during ended, an observing late joiner still sees A's original name/result; it must not change to a draw or a different winner. If fewer than 2 players remain after reset, status returns to waiting with no result. Another eligible player joining starts the next round.
6. **Late joins:** Join C while A/B round is active. C sees `Waiting for next round`, current match state and the eventual result. C has no gameplay ship, cannot fly/shoot/melee/reload, take damage, block bullets, become alien or count toward surviving humans. End the A/B round. At reset A/B/C become humans in the new three-player roster, count 3. Eliminate B while A/C live: match stays active and all P2S6 alien respawn/melee/protection behavior remains available. Alien B leaving does not end the round or change count 2.
7. **Draw:** A legitimate reciprocal/trade kill in the same simulation tick must produce `DRAW` for all clients, never an alien winner. The result freezes and resets identically. For deterministic development verification, run `npx tsx --test --test-name-pattern='same tick reciprocal' tests/match.test.ts` and `npx playwright test tests/match.spec.ts --workers=1`: the real projectile path resolves both lethal bullets before the server evaluates the result; the browser cases verify DRAW from server snapshots. No public client draw/winner command or clock control was added. Manual trade reproduction can use point-blank opposing human shots after reducing shields/HP with existing development self-damage controls; exact network/tick timing may require retries.
8. **Latency:** Enable existing F3 fake network latency/jitter for A/B before repeating victory, freeze and reset, and test spectator-to-participant transition. All clients must agree on round, roster and result. Human gun cadence, reload, prediction/reconciliation and active-round P2S6 melee damage/range/protection remain unchanged. No duplicate results, stale overlays, double resets or alien visuals after reset.

## Architecture and checks

`shared/match.ts` defines replicated waiting/active/ended state, monotonic round, locked roster, discriminated winner/draw result, simulation-time end timestamp and reset remaining duration. `server/match.ts` owns transitions and six-second reset in the existing fixed tick. Winner detection runs after the entire player/projectile damage batch, enabling trade draws. Disconnect removal immediately evaluates an active round only. Winner ID/name are copied at end and never recalculated during ended.

Private `gameplayEnabled` gates central damage/resources, movement, respawn and fire APIs. OUT late joiners are excluded from target collision and melee. Ended freezes all connected players, clears projectiles and cancels respawn deadlines. Reset validates every safe spawn before atomically restoring connected players, synchronizing player simulation clocks and clearing alien/combat/lifecycle residue and starting a new locked roster with at least two humans; otherwise waiting. It preserves membership identity and monotonic request counters while advancing life/teleport markers. Projectile IDs also remain monotonic. No per-player/room timeout or new frame loop.

The client renders result names via textContent only, never computes a winner from counts. Match boundaries clear delayed input/action callbacks, prediction/projectile visuals, held keys and hit feedback. Existing prediction/reconciliation logic stays unchanged during gameplay. Spectator ships are not rendered; no spectator camera system.
